# Fantacalcio Mantra analysis

Requirements: [prd/README.md](prd/README.md).
The local database uses PostgreSQL 18 in Docker Compose with persistent storage.

## Start

With Docker running and Docker Compose installed:

```bash
cp .env.example .env
# Edit .env and replace POSTGRES_PASSWORD with your own password.
docker compose up -d --wait
docker compose ps
```

Connect at `127.0.0.1:5432` using the database, username, and password in `.env`.
Change `POSTGRES_PORT` if the port is occupied. Other services added to this
Compose project can connect at `db:5432`. `.env` is ignored by Git.

Open a SQL shell:

```bash
docker compose exec db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
```

Use `\dt` to list tables and `\q` to exit. The database starts with empty tables.

## Import players from Excel

From the project directory, install the Python dependencies and preview the data:

```bash
uv sync
uv run python -m project.etl.import_players --dry-run
```

With PostgreSQL running, import the players:

```bash
uv run python -m project.etl.import_players
```

The default input is `data/Quotazioni_Fantacalcio_Stagione_2026_27.xlsx`.
Pandas reads `Id`, `Nome`, `RM` (or `Rm`), and `Squadra` below the title row.
The script reads connection settings from `.env`; environment variables take
precedence. `POSTGRES_HOST` optionally overrides the default `127.0.0.1`.

To select another workbook and season:

```bash
uv run python -m project.etl.import_players data/another_file.xlsx --season 2025
```

The original Excel ID is stored in `player_source_id.external_id`; internal
player IDs are generated by PostgreSQL. Names, teams, and dated roles are saved
in the existing related tables, including multi-role combinations containing B.
Reimporting identical file contents reuses the original snapshot time and updates
existing records. Each successful run adds a collection record. The entire
import rolls back on failure; failures are reported in the terminal.

For a known extraction date, pass `--snapshot-at 2026-09-07T12:00:00+02:00`.
Otherwise the first import time is used and retained for repeat imports. Names
are preserved as supplied, including any source markers. This imports player
details only, not ratings or valuations.

Inspect the imported data in psql:

```sql
SELECT ids.external_id AS id, p.name, t.name AS team,
       string_agg(r.role, ';' ORDER BY r.role) AS roles,
       s.season, s.snapshot_at
FROM player_season_snapshot s
JOIN player p ON p.id = s.player_id
JOIN player_source_id ids ON ids.player_id = p.id AND ids.source_id = s.source_id
JOIN team t ON t.id = s.team_id
JOIN player_snapshot_role r ON r.snapshot_id = s.id
GROUP BY s.id, ids.external_id, p.name, t.name
ORDER BY p.name;
```

## Collect historical matchday data

The historical scraper imports all players and fixtures for **2023–24,
2024–25, and 2025–26** from Fantacalcio.it (38 matchdays per season).
It uses **Redazione Fantacalcio** for both Voto and published Fanta Voto.
Current-season collection is not part of the default run.

Install dependencies and validate a small sample without connecting to PostgreSQL:

```bash
uv sync
uv run python -m project.etl.scrape_seasons --seasons 2023 2024 2025 --matchdays 1 --dry-run
```

With PostgreSQL running and a backup saved, collect and import all three seasons:

```bash
uv run python -m project.etl.scrape_seasons
```

Options:

| Option | Behavior |
| --- | --- |
| `--seasons 2023 2024 2025` | Season start years; these are the defaults |
| `--matchdays 1 2 38` | Explicit matchdays; defaults to 1–38 |
| `--dry-run` | Download/cache and validate; no database connection or writes |
| `--refresh` | Fetch new HTML and reconcile even previously imported pages |
| `--cache-dir PATH` | Override `data/cache/fantacalcio` |
| `--env-file PATH` | Override the project `.env`; environment variables take precedence |

Run the same command again after an interruption. Valid cached HTML is reused;
successfully imported batches from the same parser version are skipped. Failed
or incomplete pages are fetched again. Each request has a 30-second timeout;
downloads are sequential, at least two seconds apart, with up to three attempts
for connection errors, timeouts, HTTP 429, and HTTP 5xx. Longer `Retry-After`
delays are honored. Redirects and unexpected season/matchday selections fail
validation.

Original HTML is stored by checksum under `<cache>/<season>/<matchday>/` with
a `latest.json` manifest recording its URL and retrieval time. These files and
`<cache>/coverage.json` are ignored by Git; back them up with PostgreSQL. The
coverage report describes the latest command's requested matchdays, fixture and
performance counts, unresolved pages, and any canonical/historical name
differences encountered during imports. An incomplete run exits with status 1;
an interrupted run exits with status 130. A sample run reports sample coverage,
not completeness of an entire season.

Each validated matchday is imported in one transaction. Incomplete pages cannot
replace earlier validated performances. Failed/incomplete collection attempts
remain in `collection_record`, and their downloaded HTML remains cached. A
refreshed complete page updates existing observations and removes rows that the
source no longer publishes for those fixtures and that provider.

Players are linked by Fantacalcio ID, including players outside the current
auction list. The scraper creates missing historical identities but preserves
existing canonical names and current eligibility snapshots. Teams are matched
by trimmed, case-insensitive canonical names; fixture teams retain transfers.
Source names and Classic roles stay in raw values; historical Classic roles
are not converted into Mantra eligibility.

Source rating codes `55` and `56` are treated as unrated, with null Voto/Fanta
Voto; raw tokens are retained. Missing values remain null and event zeroes
remain zero. Cards use the selected provider's `yellow-card`/`red-card` flags;
a red flag alone does not reveal an earlier yellow or a second-yellow dismissal.
Dates use `Europe/Rome`. Minutes, starting status, and actual appearance remain
null because their semantics have not been verified. Absence from a page does
not establish non-participation. Published Fanta Voto is never recomputed or
given additional bonuses; goal/penalty categories and extra events such as
Player of the Match are retained without assumed scoring weights.


## Persistence

The named Docker volume `fantacalcio_postgres_data` retains data when the
container is recreated, including with:

```bash
docker compose down
docker compose up -d --wait
```

**`docker compose down -v` deletes the volume and its data.** A persistent volume
is not a backup.

[db/init/001_schema.sql](db/init/001_schema.sql) initializes an empty volume.
See [db/README.md](db/README.md) for the design and import conventions.
Initialization scripts run only on first startup: later schema changes need
explicit migrations, not volume deletion. Changing credentials in `.env` also
does not change credentials in an initialized database.

The volume mounts at `/var/lib/postgresql`, as required by the
[official PostgreSQL 18 image](https://hub.docker.com/_/postgres).
Keep the major version fixed; major upgrades require a database migration.

## Backup and restore

Create a backup before imports or schema changes, using a new filename each time:

```bash
mkdir -p backups
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > backups/fantacalcio.dump
```

Restore into a new, empty database:

```bash
docker compose exec db sh -c 'createdb -U "$POSTGRES_USER" fantacalcio_restore'
docker compose exec -T db sh -c 'pg_restore --exit-on-error --no-owner -U "$POSTGRES_USER" -d fantacalcio_restore' < backups/fantacalcio.dump
```

Backups are ignored by Git. Keep a copy outside this machine for recovery from
disk loss. View startup errors with `docker compose logs db`.
